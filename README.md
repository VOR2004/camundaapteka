# Т-Аптеки: отслеживание заказа в Camunda 8

Учебный проект: исполняемый BPMN-процесс отслеживания заказа и Java-мок API. Пользователь берёт и завершает задачи в Tasklist, сервис получает статус по HTTP, а выполнение процесса видно в Operate. Мок заменяет внешнюю систему аптеки/API банка; к реальному банку проект не подключается.

## Состав

```text
camunda/
  t-apteka-tracking.bpmn   # схема процесса
  request_order.form      # ввод номера заказа
  view_status.form        # просмотр статуса
  refresh_order.form      # запрос обновления
  start-variables.json    # переменные для нового экземпляра
src/main/java/ru/itis/Main.java
src/main/resources/static/
  index.html              # страница управления статусами
  app.js
  styles.css
```

## Требования

- JDK 17 или новее для Java-мока. Gradle Wrapper включён в репозиторий; при первом запуске ему нужен интернет для загрузки Gradle.
- Camunda Desktop Modeler и отдельно запущенная Camunda 8 Run. BPMN подготовлена и проверена на Camunda 8.10.6, Modeler 5.52.0.
- Требования к Java для Camunda Run зависят от её версии; используйте комплектный runtime официальной сборки.

## 1. Запуск Java-мока

Откройте проект в IntelliJ IDEA как Gradle-проект. После синхронизации откройте `Main.java` и нажмите **Run** рядом с `main`.

Либо из корня репозитория:

```cmd
gradlew.bat run --console=plain
```

В Linux/macOS:

```sh
./gradlew run --console=plain
```

Страница: http://localhost:3001. Проверка: http://localhost:3001/health — ответ `{"status":"UP","runtime":"java"}`.

Остановка: **Stop** в IDEA или **Ctrl+C** в терминале, где запущен Gradle. Java-мок не запускается скрыто в фоне. Если порт занят, сервер сообщит об этом и завершится. Другой порт передаётся первым аргументом `main`, для Gradle: `gradlew.bat run --args="3101"`. В таком случае также измените `apiBaseUrl` в Camunda.

## 2. Запуск Camunda Run

Скачайте и распакуйте официальную Camunda 8 Run отдельно от репозитория. Из её каталога в Windows выполните:

```cmd
c8run.exe start
```

Для стандартной локальной конфигурации:

- Tasklist: http://localhost:8080/tasklist
- Operate: http://localhost:8080/operate
- Вход: `demo` / `demo`

Это данные локальной демонстрационной сборки, не учётная запись реального сервиса. Дистрибутив Camunda и её рабочие данные не включены в Git.

## 3. Развёртывание форм и BPMN

В Desktop Modeler создайте подключение:

| Поле | Значение |
|---|---|
| Target | Camunda 8 Self-Managed |
| REST / Cluster endpoint | `http://localhost:8080/v2` |
| Authentication | None |

Сначала откройте каждую из трёх `.form` в папке `camunda` и выполните **Deploy Form**. Затем откройте `camunda/t-apteka-tracking.bpmn` и выполните **Deploy**.

Во всех задачах используется привязка формы `Latest`: формы можно загружать отдельно, но перед запуском экземпляра они должны быть развёрнуты. Тексты форм редактируются в визуальном редакторе Modeler; после изменения форму нужно сохранить и снова развернуть. Уже открытая задача может продолжить показывать ранее выбранную версию формы.

Нажмите **Start instance / Run** и укажите переменные из `camunda/start-variables.json`:

```json
{
  "orderId": "1001",
  "apiBaseUrl": "http://localhost:3001",
  "continueTracking": true
}
```

`localhost:3001` подходит для локального Camunda Run. При запуске Connector Runtime в Docker/SaaS настройте доступный из него адрес мока.

## 4. Демонстрация

1. В Tasklist откройте «Запросить статус заказа», нажмите **Assign to me**, оставьте `1001` и нажмите **Complete Task**.
2. Мок вернёт `PAID`. Возьмите задачу «Просмотреть статус заказа», оставьте флажок продолжения и завершите её.
3. На http://localhost:3001 выберите `ASSEMBLING` и сохраните статус.
4. В Tasklist возьмите и завершите «Запросить обновление». Новая задача просмотра покажет изменённый статус.
5. Повторите для `READY`, затем `DELIVERED`. После просмотра `DELIVERED` процесс завершится. `CANCELLED` также завершает процесс. Снятый флажок закрывает просмотр раньше.

В Operate откройте активный экземпляр для просмотра положения токена и истории. Назначение задачи себе не двигает токен: его продвигает завершение задачи. Изменение статуса на странице мока не отправляет событие в Camunda — процесс ждёт ручной запрос обновления.

## API мока

| Метод и путь | Назначение |
|---|---|
| `GET /` | HTML-страница из отдельного файла |
| `GET /orders` | Список заказов в JSON |
| `GET /orders/{orderId}` | Один заказ или 404 |
| `POST /set` | Смена статуса через HTML-форму |
| `GET /health` | Проверка работоспособности |

`POST /set` принимает `application/x-www-form-urlencoded`: `orderId=1001&status=READY`, возвращает 303 на `/`.

```json
{
  "orderId": "1001",
  "status": "PAID",
  "updatedAt": "2026-11-09T12:00:00Z"
}
```

Статусы: `PAID`, `ASSEMBLING`, `READY`, `DELIVERED`, `CANCELLED`. Данные хранятся в памяти. После перезапуска заказ `1001` снова `PAID`; другие созданные заказы исчезают. Через форму можно создать новый номер заказа.

## Остановка

1. Остановите Java-мок кнопкой **Stop** в IDEA или **Ctrl+C** в его терминале.
2. В каталоге Camunda Run выполните `c8run.exe stop`.

Закрытие Modeler или браузера не выключает серверы. Остановка Camunda не отменяет сохранённые экземпляры процессов.

## Ограничения

Это локальный учебный мок без авторизации и постоянного хранения. Неизвестный заказ возвращает 404; отдельная бизнес-ветка для него в BPMN не реализована. Недоступность мока и HTTP-ошибки могут создать инцидент в Operate. Используйте существующий заказ `1001` или предварительно создайте другой через страницу мока.
